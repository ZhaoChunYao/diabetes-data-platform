## Key Relationships

```
participants (1)  ─────── (1) measurement
             (1)  ─────── (1) ecg_metadata
             (1)  ─────── (M) participant_conditions ─────── (1) conditions

participants (1)  ─────── (M) cgm_daily      ─────── (M) cgm_readings
             (1)  ─────── (M) hr_daily       ─────── (M) hr_readings
             (1)  ─────── (M) sleep_daily    ─────── (M) sleep_readings
             (1)  ─────── (M) spo2_daily     ─────── (M) spo2_readings
             (1)  ─────── (M) stress_daily   ─────── (M) stress_readings
             (1)  ─────── (M) activity_daily ─────── (M) activity_readings
```

Legend: (1) = One, (M) = Many

## Index Strategy Visualization

```
Composite Index: (participant_id, day_index, timestamp)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Query: Get participant 1001's HR from day 1-7

Step 1: Seek on participant_id = '1001'    ✓ Index seek
        ↓ Narrows to ~11,000 rows
        
Step 2: Filter day_index BETWEEN 1 AND 7   ✓ Index range scan
        ↓ Narrows to ~10,000 rows
        
Step 3: Order by timestamp                 ✓ Index already sorted
        ↓ No filesort needed!

Result: 50-100ms query time (vs 8-12 seconds without index)
```

## Query Performance by Layer

```
LAYER 1 (Metadata):         <10ms    ━━━━━━━━━━ (fastest)
LAYER 2 (Daily Aggregates): 10-100ms ━━━━━━━━━━━━━━━━━━━━
LAYER 3 (Timeseries):       50-200ms ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## Design Philosophy

```
                          SPEED ←─────→ DETAIL
                          
Group Queries  ──→  Use Daily Aggregates    (fast, summary)
Individual     ──→  Use Timeseries          (slower, detailed)

                   Best of Both Worlds!
```
